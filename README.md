# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

Приложение работает с двумя основными сущностями: товары и информация о покупателе. Для их описания используются следующие интерфейсы:

### Интерфейс IProduct

Описывает структуру товара в приложении:

```typescript
interface IProduct {
  id: string;           // Уникальный идентификатор товара
  description: string;  // Описание товара
  image: string;        // URL изображения товара
  title: string;        // Название товара
  category: string;     // Категория товара
  price: number | null; // Цена товара (может быть null)
}
```

Этот интерфейс используется для представления товаров в каталоге, где каждый товар имеет уникальный идентификатор, визуальную информацию (название, описание, изображение), категоризацию и ценовую информацию.

### Интерфейс IBuyer

Описывает структуру данных покупателя при оформлении заказа:

```typescript
interface IBuyer {
  payment: TPayment;  // Способ оплаты (тип TPayment)
  email: string;      // Электронная почта покупателя
  phone: string;      // Номер телефона покупателя
  address: string;    // Адрес доставки
}
```

Этот интерфейс определяет необходимые данные, которые должны быть собраны от покупателя для успешного оформления заказа.

## Модели данных

Слой Model реализован через три класса, которые разделены по смыслу и зонам ответственности. Каждый класс отвечает за управление определенным аспектом данных приложения.

### Класс CatalogModel

**Назначение и зона ответственности:**  
Класс отвечает за управление каталогом товаров и хранение информации о товаре, выбранном для подробного просмотра. Он обеспечивает получение, сохранение и управление списком товаров, доступных для покупки.

**Конструктор:**  
`constructor()` - конструктор не принимает параметров. Инициализирует пустой массив товаров и отсутствие выбранного товара.

**Поля класса:**  
`products: IProduct[]` - массив всех товаров, доступных в каталоге. Хранит полный список товаров, полученных с сервера.  
`selectedProduct: IProduct | null` - товар, выбранный для подробного отображения. Используется для отображения модального окна с детальной информацией о товаре.

**Методы класса:**  
`setProducts(products: IProduct[]): void` - сохраняет переданный массив товаров в поле `products` класса. Используется для инициализации каталога данными с сервера. Генерирует событие об изменении каталога.  
`getProducts(): IProduct[]` - возвращает массив всех товаров из каталога.  
`getProduct(id: string): IProduct | undefined` - принимает строку с идентификатором товара и возвращает объект товара по его id или `undefined`, если товар не найден.  
`setSelectedProduct(product: IProduct): void` - принимает товар и сохраняет его как выбранный для подробного просмотра. Генерирует событие о выборе товара.  
`getSelectedProduct(): IProduct | null` - возвращает товар, выбранный для подробного отображения, или `null`, если ни один товар не выбран.

### Класс BasketModel

**Назначение и зона ответственности:**  
Класс управляет корзиной покупателя и хранит товары, которые пользователь выбрал для покупки. Он обеспечивает добавление, удаление товаров, расчет стоимости и управление состоянием корзины.

**Конструктор:**  
`constructor()` - конструктор не принимает параметров. Инициализирует пустой массив товаров в корзине.

**Поля класса:**  
`items: IProduct[]` - массив товаров, выбранных покупателем для покупки. Каждый элемент массива — это объект товара, добавленный в корзину.

**Методы класса:**  
`getItems(): IProduct[]` - возвращает массив всех товаров, находящихся в корзине.  
`addItem(product: IProduct): void` - принимает объект товара и добавляет его в массив корзины. Генерирует событие об добавлении товара в корзину.  
`removeItem(product: IProduct): void` - принимает объект товара и удаляет его из массива корзины. Если товар не находится в корзине, ничего не происходит. Генерирует событие об удалении товара из корзины.  
`clear(): void` - очищает корзину, удаляя все товары. Генерирует событие об очистке корзины.  
`getTotal(): number` - возвращает общую стоимость всех товаров в корзине. Суммирует значения цен всех товаров в массиве.  
`getCount(): number` - возвращает количество товаров в корзине. Возвращает длину массива `items`.  
`hasItem(id: string): boolean` - принимает строку с идентификатором товара и возвращает `true`, если товар с таким id находится в корзине, иначе возвращает `false`.

### Класс BuyerModel

**Назначение и зона ответственности:**  
Класс отвечает за хранение и управление данными покупателя при оформлении заказа. Он обеспечивает сохранение, получение, валидацию и очистку информации о способе оплаты, контактных данных и адресе доставки.

**Конструктор:**  
`constructor()` - конструктор не принимает параметров. Инициализирует объект с пустыми значениями полей покупателя.

**Поля класса:**  
`buyer: IBuyer` - объект, содержащий данные покупателя. Хранит информацию о способе оплаты, email, телефоне и адресе доставки. Все поля могут быть пустыми строками или null в зависимости от этапа заполнения формы.

**Методы класса:**  
`setBuyerData(data: Partial<IBuyer>): void` - принимает частичный объект с данными покупателя и обновляет соответствующие поля в классе. Позволяет обновить только необходимые поля без удаления существующих данных. Например, можно передать `{ email: 'user@example.com' }` и адрес останется неизменным. Генерирует событие об изменении данных покупателя.  
`getBuyerData(): IBuyer` - возвращает объект со всеми текущими данными покупателя.  
`clearBuyerData(): void` - очищает все данные покупателя, устанавливая все поля в пустые значения. Генерирует событие об очистке данных покупателя.  
`validateBuyerData(): Partial<Record<keyof IBuyer, string>>` - проверяет корректность данных покупателя. Возвращает объект, в котором ключи — это названия полей, а значения — сообщения об ошибках. Если поле валидно, оно не включается в объект ответа. Поле считается валидным, если оно не пусто. Пример возвращаемого значения при ошибках:
```typescript
{
  payment: 'Не выбран вид оплаты',
  email: 'Укажите email'
}
```
Если все поля заполнены корректно, метод возвращает пустой объект `{}`.

Все классы слоя Model генерируют события при изменении данных, используя механизм EventEmitter. Это позволяет слою Presenter отслеживать изменения и обновлять представление соответственно.

## Слой коммуникации

Слой коммуникации отвечает за взаимодействие приложения с сервером. Он инкапсулирует логику отправки запросов и получения данных, используя композицию с классом `Api` для выполнения HTTP операций.

### Типы данных для работы с сервером

#### Интерфейс IProductsResponse

Описывает структуру ответа сервера при запросе списка товаров:

```typescript
interface IProductsResponse {
  total: number;        // Общее количество товаров
  items: IProduct[];    // Массив объектов товаров
}
```

#### Интерфейс IOrderData

Описывает структуру данных заказа, отправляемых на сервер:

```typescript
interface IOrderData {
  payment: TPayment;   // Способ оплаты ('card' или 'cash')
  email: string;       // Email покупателя
  phone: string;       // Телефон покупателя
  address: string;     // Адрес доставки
  items: string[];     // Массив идентификаторов товаров в заказе
  total: number;       // Общая сумма заказа
}
```

#### Интерфейс IOrderResponse

Описывает структуру подтверждения заказа, полученного от сервера:

```typescript
interface IOrderResponse {
  id: string;    // Идентификатор оформленного заказа
  total: number; // Сумма заказа
}
```

### Класс ApiService

**Назначение и зона ответственности:**  
Класс обеспечивает коммуникацию приложения с API сервера. Он использует композицию, принимая в конструктор объект, реализующий интерфейс `IApi`, и предоставляет методы для получения списка товаров и отправки заказов на сервер. Класс полностью инкапсулирует HTTP операции, скрывая детали реализации от остального приложения.

**Конструктор:**  
`constructor(api: IApi)` - принимает объект, реализующий интерфейс `IApi`, для выполнения HTTP запросов.

**Поля класса:**  
`api: IApi` - приватное поле для хранения объекта API, используется для выполнения GET и POST запросов.

**Методы класса:**  
`getProducts(): Promise<IProductsResponse>` - выполняет GET запрос на эндпоинт `/product/` и возвращает Promise с объектом ответа, содержащим массив товаров и их общее количество. Используется для получения списка всех доступных товаров при загрузке приложения.  
`submitOrder(orderData: IOrderData): Promise<IOrderResponse>` - принимает объект с данными заказа и выполняет POST запрос на эндпоинт `/order/`, отправляя эти данные на сервер. Возвращает Promise с объектом подтверждения заказа, содержащим идентификатор заказа и финальную сумму. Используется для отправки оформленного заказа на сервер.
